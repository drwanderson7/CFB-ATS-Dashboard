Methodology

Last updated: August 2026

PickGauge doesn't run its own prediction model from scratch. Model # is a weighted average of computer prediction systems and market data pulled from outside sources, plus optional context from a sports-data provider. This page explains what those sources are, what they're used for, and — for the sources this matters most for — that PickGauge isn't affiliated with or endorsed by any of them.

What Model # actually is

Every prediction system you enable in the Prediction Systems panel becomes one number in a weighted average (default: equal weight, adjustable per system). That average — Model # — is compared against the market line to produce Edge and Cover %. It's a simple, transparent average, not a trained model of PickGauge's own, and it's only ever as good as the systems feeding into it.

Data sources

Prediction systems
Aggregated computer prediction systems

The great majority of Model #'s inputs — every named computer rating and prediction system in the checklist (Sagarin variants, Massey Ratings, ESPN FPI, and the rest) — come from a third-party source that aggregates weekly predictions from dozens of independent computer rating systems. PickGauge is not affiliated with or endorsed by that source, or by any of the individual rating systems themselves. If you run one of these systems and have questions about how your data is used here, please reach out.

Live lines & scores
The Odds API

Live and historical sportsbook spreads shown on the Edge Board come from The Odds API, a commercial odds-data provider PickGauge has a paid account with.

Context, not a model input (with one exception)
CollegeFootballData.com (CFBD)

Live scores, power ratings (CORE/SP+/FPI/Elo/SRS), Matchup Intelligence, postgame box scores, and historical betting-line checks all come from CollegeFootballData.com, via a paid CFBD API account. All of this is shown as context around a game — it never changes Model #, Edge, Cover %, or EV. The one deliberate exception: SP+ and CORE can optionally be enabled as real, weighted inputs to Model # (derived from the underlying CFBD rating plus a fixed home-field constant), exactly like any other prediction-system input — every other CFBD feature stays context-only. Matchup Intelligence specifically uses current-season advanced offense/defense stats with garbage-time plays excluded; it discloses early-season sample size and adds classification-aware rank/percentile context for each raw value. FBS and FCS teams are ranked separately, and the denominator is only teams with that metric currently available (important early in the season). Matchup Intelligence is hidden after a game is final so that game's own performance is not fed back into what is presented as pregame matchup context. In Results, the postgame "Why?" view instead shows the actual final score, archived ATS result/cover margin, the three largest descriptive statistical separators, and the full advanced box-score comparison. Those separators are explanatory context only, not causal weights or a prediction model.

What PickGauge itself computes

A few things shown throughout the app are PickGauge's own math, not pulled from an outside source:

  • Edge, Cover %, and EV — derived directly from Model # vs. the market line, using a cover-probability curve fitted from thousands of real historical FBS games.
  • CLV (closing-line value) — the market's move between your pick and the retained pre-kick closing line.
  • The ★ Top 10 backtest ranking — a real 2-year backtest (40% ATS% / 30% MAE / 30% |Bias|) of every enabled prediction system's own historical accuracy, used only to flag which systems have actually performed well — never to auto-weight Model # itself.

How the live model-performance record works

The Results page keeps model performance separate from your pick performance. When PickGauge has both a market line and model projections before kickoff, it freezes a compact snapshot for every available game — not only games you decide to pick. That lets each prediction system, including PickGauge Model #, be graded as a hypothetical ATS lean without selection bias from the user's own shortlist.

The comparison line is the market/book from the last pre-kick snapshot this account actually observed. It is never reconstructed from a postgame line and should not be read as a guaranteed official closing line. A model projection equal to the market is recorded as no lean; pushes are shown in W-L-P records but excluded from the win-rate denominator. Model history is prospective: PickGauge does not backfill past games using predictions available after those games were played, because that would contaminate the track record with hindsight.
